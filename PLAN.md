# MiniMedia — Implementation Plan

A minimal, Jellyfin-like home media system: a **Go server** that runs on Windows (also Linux/macOS) and serves a local movie/TV library over the LAN, and a **native Google TV app** for a Chromecast with Google TV (4K) with a Netflix-quality player.

---

## 0. Instructions for Claude Code

- Read this whole file before writing code. It is the spec; decisions here are final unless the user changes them.
- Repository layout:
  ```
  /server        Go module (github.com/<user>/minimedia/server)
  /tv-app        Android Studio project (Kotlin, Compose for TV, Media3)
  /testdata      scripts that generate sample media with ffmpeg (generated media is git-ignored)
  PLAN.md        this file
  ```
- The development machine is **Windows**. Use PowerShell-compatible commands, `filepath` (never hard-coded `/`), and test the server on Windows first.
- Work **phase by phase** (section 9). Finish a phase, run its acceptance checks, commit, then summarise what works before starting the next one.
- Generate test media with ffmpeg (section 10) instead of asking the user for files. Never modify or delete files inside the user's media folders: the server is **read-only** on libraries.
- Prefer the standard library. Allowed dependencies (server): `gopkg.in/yaml.v3`, `modernc.org/sqlite` (pure Go, no cgo, so it builds on Windows without gcc), `github.com/fsnotify/fsnotify`, `golang.org/x/sys`, `golang.org/x/text`, `golang.org/x/image`. Ask before adding others.
- Out of scope: a phone app, Chromecast casting, user accounts, authentication, remote/internet access, live TV, plugins, music, photos.

## 1. Product decisions (summary)

| Topic | Decision |
|---|---|
| Clients | Google TV app only (runs on the Chromecast with Google TV). No phone app, no casting. |
| Users | Single user, LAN only. **No authentication, no PIN.** |
| Server language | Go, single binary, cross-platform: **Windows, macOS and Linux** are all supported targets (macOS/Linux added by the user's decision, 2026-11-17; see section 7.1). |
| Configuration | **YAML config file only**, no CLI parameters. |
| Discovery | TV app finds the server automatically via UDP broadcast; manual URL entry as a fallback. |
| Playback | Direct play by default (ExoPlayer plays MKV/MP4 natively). Server-side **audio-only** conversion (video copied) for codecs the TV can't play (DTS, TrueHD). AV1 flagged unsupported in v1. |
| Subtitles | Embedded tracks plus external sidecar files (`.srt`, `.ass`, `.ssa`, `.vtt`), with encoding detection and conversion to UTF-8 (Romanian Windows-1250 / ISO-8859-2 files are common). |
| Seek thumbnails | Trickplay sprite sheets generated by the server in the background. |
| Metadata | TMDB (optional API key) with local-image and frame-grab fallbacks. |
| Player UX | Netflix-level: thumbnail scrubbing, skip intro, next-episode card, track panel, resume, **"Ends at HH:MM"** everywhere relevant. |

## 2. Configuration

### 2.1 Location (first match wins)
1. `config.yaml` in the same folder as the executable.
2. Windows: `%ProgramData%\MiniMedia\config.yaml`. macOS: `~/Library/Application Support/MiniMedia/config.yaml`. Linux: `~/.config/minimedia/config.yaml` (`$XDG_CONFIG_HOME`; skipped when run as root), then `/etc/minimedia/config.yaml`.

If no file exists: write a fully commented default `config.yaml` next to the executable (or, if that folder isn't writable, at the first writable location above), log a message telling the user to set `libraries`, and exit with a non-zero code.

### 2.2 Schema and defaults
```yaml
# Display name shown in the TV app
name: "MiniMedia"

port: 8096
discovery: true            # UDP discovery on port 7360

libraries:                 # required, at least one
  - name: Movies
    type: movies           # movies | shows
    path: 'D:\Media\Movies'      # backslashes need single quotes; D:/Media/Movies also works
  - name: Shows
    type: shows
    path: '\\nas\media\Shows'    # UNC paths are the most reliable for network shares

# default: Windows %ProgramData%\MiniMedia\data, macOS ~/Library/Application Support/MiniMedia/data, Linux ~/.local/share/minimedia (/var/lib/minimedia as root)
data_dir: ""

tmdb_api_key: ""           # empty = filenames + local images only
metadata_language: en-US   # e.g. ro-RO; falls back to English if missing on TMDB

subtitles:
  preferred_languages: [en]       # ISO 639-1, order = priority
  fallback_encoding: windows-1250 # used when a sidecar isn't valid UTF-8/UTF-16

playback:
  audio_convert: auto      # auto | always | never

trickplay:
  enabled: true
  interval_seconds: 10
  width: 320
  max_parallel_jobs: 1

scan:
  watch_folders: true
  rescan_every_hours: 24

ffmpeg: ""                 # empty = look next to the executable, then PATH
ffprobe: ""

log_level: info            # debug | info | warn | error
log_file: ""               # empty = stderr only; a path also writes there (rotated at 10 MB, 3 old files kept)
```

- Parse with `yaml.v3` and `decoder.KnownFields(true)`: unknown or misspelled keys are a startup error that names the key and line.
- Validate: each library path exists and is readable, `type` valid, port free, ffmpeg/ffprobe found (`-version` runs). Print all errors at once.
- Config changes require a restart. Media folder changes are picked up live (section 3.5).

## 3. Server: library

### 3.1 Storage
SQLite (`modernc.org/sqlite`) at `data_dir/minimedia.db`, WAL mode. Tables (suggested):

- `items` — id (stable: first 16 hex chars of SHA-1 of the normalised absolute path), library, kind (`movie` | `episode`), path, size, mtime, title, sort_title, year, show_id, season, episode, episode_end (multi-episode files), overview, runtime_ms, added_at, probe_json, tmdb_id, rating, genres, keyframes_cached (bool), trickplay_state.
- `shows` — id, library, folder path, title, year, overview, tmdb_id, genres.
- `subtitles` — id, item_id, source (`embedded` | `external`), stream_index or path, language, label, forced, sdh, codec.
- `images` — owner_id, kind (`poster` | `backdrop` | `logo` | `still`), source (`local` | `tmdb` | `frame`), path/url, cached_path.
- `progress` — item_id, position_ms, duration_ms, watched, play_count, last_played_at.
- `show_prefs` — show_id, audio_language, subtitle_language, subtitles_mode (`off` | `on` | `forced_only`).
- `markers` — item_id, kind (`intro` | `recap` | `credits`), start_ms, end_ms, source (`chapter`).

### 3.2 Scanning and naming
Video extensions: `.mkv .mp4 .m4v .mov .avi .ts .m2ts .webm .wmv`.
Ignore: folders named `Extras, Featurettes, Behind The Scenes, Deleted Scenes, Interviews, Trailers, Samples, Sample, Other`, files containing `sample` (as a separate token) smaller than 300 MB, hidden/system files, `$RECYCLE.BIN`, `System Volume Information`, `@eaDir`, `.trickplay`.

**Movies** (`type: movies`):
- `Title (Year)/Title (Year).ext`, `Title (Year).ext`, and scene names like `Title.Year.1080p.BluRay.x264-GRP.mkv`.
- Title = folder name when the file is the only video in a folder named `Title (Year)`; otherwise the file name.
- Scene-name cleanup: replace `.` and `_` with spaces; cut at the first year token (1900–2099) or the first quality/source tag (`2160p, 1080p, 720p, 4k, bluray, bdrip, brrip, web-dl, webrip, web, hdtv, remux, hdr, dv, x264, x265, h264, h265, hevc, aac, dts, ddp5.1, atmos`, …), case-insensitive. Strip bracketed groups `[...]`.
- **TV mixed into a movies library** (Jellyfin-style download folders; added after Phase 3): a file whose name has an explicit season+episode code (`S01E02`, `1x02`; never a bare `E02`/`Episode 4`) is an episode, not a movie. The show name is the nearest folder that isn't a `Season N` folder (a season-pack folder `Show.Name.S01.1080p…` gives `Show Name`) when it matches the text before the code in the file name, or when the file name has none; otherwise the text before the code. Episodes are grouped into one show per name across the library (loose files and folders together). Show artwork and `tmdb.txt` come from the show's folder, if it has one. A file with a code but no show name anywhere is unmatched.

**Shows** (`type: shows`):
- Show = first-level folder under the library path (`Shows/Show Name (Year)/…`).
- Season from a `Season NN` / `Season N` / `S01` folder, `Specials` = season 0.
- Episode from the file name: `S01E02`, `s01e02`, `S01E02-E03` / `S01E02E03` (multi-episode), `1x02`. If the file only has `E02`/`Ep 02`, use the season from the folder.
- Episode title = text after the SxxEyy token and separators (`Show - S01E02 - Title.mkv`), cleaned like scene names.
- Files that don't parse are logged at warn level and skipped (and listed in `GET /api/library/unmatched`).

### 3.3 Probing
`ffprobe -v error -print_format json -show_format -show_streams -show_chapters <file>`. Store the JSON. Derive per item:
- video: codec, profile, width, height, fps, bit depth, HDR type (`sdr | hdr10 | hlg | dv` — DV from side_data or `codec_tag`/`dvhe`/`dvh1`), DV profile.
- audio tracks: index, codec, channels, layout, language, title, default flag.
- embedded subtitle tracks: index, codec, language, title, forced, default.
- chapters → markers (section 3.6).

Re-probe only when size or mtime changes.

### 3.4 External subtitles
For a video `X.ext` match, in the same folder and in a `Subs/` or `Subtitles/` subfolder:
- `X.srt`, `X.<lang>.srt`, `X.<lang>.forced.srt`, `X.<lang>.sdh.srt`, `X.<lang>.cc.srt`, `X.<label>.<lang>.srt`.
- Also `Subs/X/*.srt` (common release layout, files like `2_English.srt`; take the language from the name).
- Same rules for `.ass`, `.ssa`, `.vtt`.
- Language tokens: ISO 639-1 (`ro`), 639-2 (`ron`, `rum`, `eng`) and English names (`Romanian`, `English`) → normalise to 639-1. Unknown → `und`.
- Label shown to the user: `Romanian`, `English (Forced)`, `English (SDH)`; duplicates get `#2`.

**Encoding** (applied when serving, cached as UTF-8 in `data_dir/subs/`):
1. Strip a UTF-8 BOM; UTF-16 LE/BE BOM → decode.
2. Valid UTF-8 → keep.
3. Otherwise decode with `subtitles.fallback_encoding` (`golang.org/x/text/encoding/charmap`). Heuristic improvement: if the language is `ro`, try Windows-1250 and ISO-8859-2 and pick the one producing more of `ăâîșțşţ` and fewer control characters.
4. Normalise Romanian cedilla characters to comma-below: `ş→ș, Ş→Ș, ţ→ț, Ţ→Ț` (only for `ro` subtitles).
5. Normalise line endings to `\n`.

### 3.5 Watching and rescans
- `fsnotify` recursively on each library (on Windows this works for local drives). Debounce events for 5 s, then rescan only the affected folder. New `.srt` files attach to existing items without re-probing.
- Periodic full rescan every `rescan_every_hours` (this is what catches changes on network shares).
- Removed files are removed from the DB; their progress is kept for 30 days in case the file comes back (match by relative path).
- `POST /api/library/scan` triggers a full scan.

### 3.6 Markers (skip intro / credits)
From chapters, case-insensitive title match:
- intro: `intro, opening, op, opening credits, title sequence`
- recap: `recap, previously, previously on`
- credits: `credits, ending, ed, end credits, outro`

No credits marker → the app uses `max(duration - 30s, 90% of duration)` as the "next episode" trigger.

### 3.7 Metadata (TMDB, optional)
- Only when `tmdb_api_key` is set. Use the v3 API with `api_key` or a v4 bearer token (detect by length/format).
- Movies: `/search/movie?query=&year=` → `/movie/{id}?append_to_response=images,release_dates&include_image_language=<lang>,en,null`.
- Shows: `/search/tv?query=&first_air_date_year=` → `/tv/{id}` → `/tv/{id}/season/{n}` for episode titles, overviews and stills.
- Store title, overview, genres, rating, runtime, poster, backdrop, **logo** (used for the home hero), and episode stills.
- Manual override: a file `tmdb.txt` containing the TMDB id in the movie or show folder takes priority over search.
- Rate limit to ~20 requests/s and cache responses. Metadata is fetched after the scan in the background and never blocks the library.

### 3.8 Images
Priority: local file → TMDB → frame grab.
- Local: `poster.jpg|png`, `folder.jpg`, `cover.jpg`; backdrop `fanart.jpg`, `backdrop.jpg`, `background.jpg`; logo `logo.png`, `clearlogo.png`; episode still `X-thumb.jpg`.
- Frame grab fallback: backdrop/still from 20% into the video (`ffmpeg -ss <t> -i <file> -frames:v 1 -vf scale=1280:-2`), tone-mapped if HDR (section 5.2).
- Served resized: `GET /images/{ownerId}/{kind}?w=342|780|1280|1920`. Resize with `golang.org/x/image/draw` (CatmullRom), cache to `data_dir/images/`, send `Cache-Control: max-age=604800` and an ETag.

## 4. Server: playback

### 4.1 Playback decision
The TV app sends its capabilities; the server decides:

```
POST /api/items/{id}/playback
{
  "videoCodecs": ["h264","hevc","vp9"],          // from MediaCodecList
  "hdr": ["hdr10","hlg","dv"],                    // from Display.HdrCapabilities
  "audioDecoders": ["aac","mp3","opus","flac","vorbis","ac3","eac3"],
  "audioPassthrough": ["ac3","eac3","dts"],       // from AudioCapabilities / AudioManager
  "maxChannels": 6,
  "audioTrack": 1,            // optional: chosen audio stream index
  "forceConvert": false       // set by the app when direct play failed
}
→
{
  "mode": "direct" | "hls",
  "url": "/stream/{id}/file" | "/stream/{id}/hls/{audioIndex}/main.m3u8",
  "container": "mkv",
  "audioTracks": [...],       // with "playable": true/false and the selected index
  "subtitles": [{ "id": "...", "language": "ro", "label": "Romanian", "forced": false,
                  "embedded": false, "url": "/subs/{id}/{subId}.srt", "mime": "application/x-subrip" }],
  "trickplay": { "indexUrl": "/trickplay/{id}/index.json" } | null,
  "markers": [{ "kind": "intro", "startMs": 0, "endMs": 85000 }],
  "resumeMs": 2531000,
  "durationMs": 6720000,
  "unsupportedReason": null    // e.g. "AV1 video is not supported by this device"
}
```

Rules:
- Video codec not in `videoCodecs` → `unsupportedReason` (no video transcoding in v1).
- Selected audio track playable if its codec is in `audioDecoders` or `audioPassthrough` (and channel count is fine) → `direct`.
- Otherwise, if `audio_convert` ≠ `never` → `hls` with audio converted: to **E-AC3 5.1** (`-c:a eac3 -b:a 640k`) when the device reports `eac3`, else **AC3 5.1** (`-c:a ac3 -b:a 640k`) when it reports `ac3` (added during Phase 4: a Chromecast whose TV reports only AC3 over HDMI keeps surround), else **AAC stereo** (`-c:a aac -ac 2 -b:a 256k`). Stereo/mono sources always become AAC, and so does a `forceConvert` retry (the device just failed on a codec it claimed). `audio_convert: always` forces `hls` for every file.
- Default audio track: the show's remembered language → `preferred_languages` → the file's default track.
- Embedded subtitle tracks play from the container in direct mode. In HLS mode, text-based embedded subtitles (subrip, ass, mov_text, webvtt) are extracted to `.srt`/`.vtt` and returned as sidecars; image subtitles (PGS, VobSub) are unavailable in HLS mode in v1 (say so in the label).

### 4.2 Direct play
`GET /stream/{id}/file` → `http.ServeContent` (Range, If-Range, HEAD). Correct `Content-Type` per extension (`video/x-matroska`, `video/mp4`, …).

### 4.3 HLS with audio conversion (video copied)
Goal: a **VOD** playlist with accurate durations so the TV's seek bar works from the first second, segments cut **exactly on source keyframes**.

1. **Keyframe index** (cached in `data_dir/keyframes/{id}.json`): 
   `ffprobe -v error -select_streams v:0 -show_entries packet=pts_time,flags -of csv=p=0 <file>` and keep packets whose flags contain `K`. This only demuxes, so it's fast (I/O bound). Compute it lazily on first HLS request and in the background for files that will need conversion.
2. **Segments**: walk keyframes, closing a segment at the first keyframe ≥ 6 s after the segment start (so segments are ~6 s; with sparse keyframes they're longer). The last segment ends at the duration.
3. **Playlist** `main.m3u8`: `#EXT-X-PLAYLIST-TYPE:VOD`, `#EXT-X-TARGETDURATION` = ceil(max segment), exact `#EXTINF` values, `#EXT-X-ENDLIST`. MPEG-TS segments: `seg/{n}.ts`. As built, the URL also names the target codec: `/stream/{id}/hls/{audioIndex}/{aac|ac3|eac3}/main.m3u8`.
4. **Transcode jobs**: one ffmpeg per (item, audio index), producing consecutive segments from a start segment:
   ```
   ffmpeg -nostdin -loglevel error
     -ss <keyframe time of segment N> -copyts -i <file>
     -map 0:v:0 -map 0:<audioIndex>
     -c:v copy -c:a <aac|eac3> <audio options>
     -sn -dn -map_metadata -1 -map_chapters -1
     -avoid_negative_ts disabled -muxdelay 0
     -f segment -segment_format mpegts
     -segment_times <comma-separated absolute boundary times after N>
     -segment_start_number N -segment_list_type flat -segment_list <jobdir>/list.txt
     <jobdir>/%05d.ts
   ```
   (HEVC in MPEG-TS needs nothing extra; verify `-copyts` + `-segment_times` produce the expected boundaries with a test and adjust if needed.)
   **As built (verified with ffmpeg 7.1, `internal/hls` tests):** stream copy starts at whatever keyframe the container index lands on, so the job seeks to just before keyframe N (`-ss K−0.001`) and drops earlier video packets with `-bsf:v noise=drop=lt(pts*tb\,K−0.001)`; the segment muxer measures `-segment_times` from the job's first packet, so boundaries are passed relative to K (50 ms early); `-output_ts_offset 10` keeps every timestamp positive (otherwise ffmpeg shifts only a job's first segment by the B-frame/priming offset and jobs don't line up). Each job writes into its own folder (no segment is ever overwritten while served); a job stops when it reaches segments another job already made. On Windows, cancelling kills the whole process tree (Chocolatey/Scoop install ffmpeg as a shim that runs the real ffmpeg as a child).
   - A segment is "ready" once it appears in `list.txt` (the segment muxer writes the entry after closing the file).
   - Request for segment `n`: if ready → serve. If a job for this item/audio is running and `n` is within `[jobStart, lastReady + 10]` → wait up to 20 s for it. Otherwise kill the job and start a new one at `n` (this is a seek).
   - Jobs run to the end of the file (copying video is ~50–200× realtime). Kill jobs idle for 2 min (no segment requests). Delete job folders idle for 6 h; cap the HLS cache at 20 GB (oldest first).
   - Files whose audio is anything but AAC/MP3/Opus/FLAC/Vorbis/PCM get their keyframe index and embedded text subtitles prepared in the background after scans (one file at a time, low priority), so a first conversion starts in seconds.
5. Serve `.ts` with `video/mp2t`, playlist with `application/vnd.apple.mpegurl`.

### 4.4 Subtitles endpoint
`GET /subs/{itemId}/{subId}.srt|.ass|.vtt` → UTF-8 converted file (section 3.4), cached. Extraction of embedded text tracks: `ffmpeg -i <file> -map 0:<idx> -c:s srt out.srt` (or `copy` for ASS).

### 4.5 Progress
- `PUT /api/items/{id}/progress {positionMs, durationMs, paused}` — the app calls it every 10 s while playing, on pause, on seek, and on exit.
- Watched when position ≥ 90% or past the credits marker → `watched = true`, `play_count++`, `position = 0`.
- Position < 2 min or < 3% → not stored as resumable.
- `POST /api/items/{id}/watched`, `DELETE /api/items/{id}/watched`; same for whole shows/seasons: `POST /api/shows/{id}/watched?season=N`.

## 5. Server: trickplay thumbnails

### 5.1 Format
Per item, in `data_dir/trickplay/{id}/`:
- `index.json`: `{ "intervalMs": 10000, "tileWidth": 320, "tileHeight": 180, "columns": 5, "rows": 5, "count": 672, "sheets": 27 }`
- `0.jpg … N.jpg`: sprite sheets of `columns × rows` tiles (5×5 at 320 px wide = 1600×900, small enough to decode on the TV without memory trouble). Thumbnail `i` is on sheet `i / 25`, tile `i % 25` (row-major).

### 5.2 Generation
```
ffmpeg -nostdin -loglevel error -skip_frame nokey -i <file> -an -sn -dn
  -vf "fps=1/<interval>,scale=<w>:-2,tile=5x5" -q:v 5 -fps_mode vfr <dir>/%d.jpg
```
- `-skip_frame nokey` decodes only keyframes, which is far faster (especially for 4K HEVC). The thumbnail is the keyframe nearest each interval point — good enough.
- Verify the last, partially filled sheet is written and the numbering starts at 0 (use `-start_number 0`); compute `count` from duration and confirm against the output.
- Tile height from the video aspect ratio (rounded to even). Use the display aspect ratio for anamorphic sources.
- HDR sources (`hdr10/hlg/dv`): insert tone mapping before scaling so thumbnails aren't washed out: `zscale=t=linear:npl=100,format=gbrpf32le,zscale=p=bt709,tonemap=tonemap=hable:desat=0,zscale=t=bt709:m=bt709:r=tv,format=yuv420p`. Check ffmpeg has `zscale` (`ffmpeg -filters`); if not, skip tone mapping and log a warning once.
- Queue: generated in the background after scanning, newest items first, `max_parallel_jobs` at a time, run ffmpeg at below-normal priority (Windows: `BELOW_NORMAL_PRIORITY_CLASS`; Unix: `nice`). Write to a temp folder and rename when complete. Regenerate when the file changes.
- `GET /trickplay/{id}/index.json` (404 until ready) and `GET /trickplay/{id}/{n}.jpg`, long cache headers.

## 6. Server: API (JSON over HTTP)

All under `http://<host>:<port>`, no auth. JSON uses camelCase. Errors: `{ "error": "message" }` with a proper status code.

| Method & path | Purpose |
|---|---|
| `GET /api/info` | `{ name, version, serverId, os }` |
| `GET /api/home` | `{ hero: [items], continueWatching, nextUp, recentlyAddedMovies, recentlyAddedEpisodes, movies (latest 30), shows (latest 30) }` |
| `GET /api/movies?sort=title\|added\|year&genre=` | movie summaries |
| `GET /api/shows?sort=...` | show summaries |
| `GET /api/shows/{id}` | show + seasons + episodes (with progress, runtime, still URL) |
| `GET /api/items/{id}` | full item: metadata, audio/subtitle tracks, markers, progress, image URLs, `trickplayReady` |
| `GET /api/search?q=` | movies, shows, episodes; diacritics-insensitive (ș = s), prefix match on words |
| `POST /api/items/{id}/playback` | section 4.1 |
| `PUT /api/items/{id}/progress` | section 4.5 |
| `POST/DELETE /api/items/{id}/watched` | mark watched/unwatched |
| `GET/PUT /api/shows/{id}/prefs` | remembered audio/subtitle language and mode |
| `POST /api/library/scan` | trigger full scan; `GET /api/library/status` returns scan/metadata/trickplay progress |
| `GET /api/library/unmatched` | files that couldn't be parsed |
| `GET /images/{ownerId}/{kind}?w=` | section 3.8 |
| `GET /stream/{id}/file` | direct play |
| `GET /stream/{id}/hls/{audioIndex}/main.m3u8`, `.../seg/{n}.ts` | HLS |
| `GET /subs/{itemId}/{subId}.{ext}` | subtitles |
| `GET /trickplay/{id}/index.json`, `/trickplay/{id}/{n}.jpg` | thumbnails |

Item summary shape (used in rows): `{ id, kind, title, year, showTitle?, season?, episode?, episodeTitle?, runtimeMs, positionMs, watched, posterUrl, backdropUrl, logoUrl?, stillUrl? }`.

"Next up" = for each show with recent activity, the first unwatched episode after the last watched one; exclude shows not played for 60 days.

### Discovery (UDP)
- Server listens on UDP **7360** (not Jellyfin's 7359, so both can coexist).
- Client broadcasts the ASCII payload `MINIMEDIA_DISCOVER_V1` to `255.255.255.255:7360` (and the subnet broadcast address).
- Server replies unicast to the sender: `{"name":"...","serverId":"...","url":"http://192.168.1.20:8096","version":"..."}`. Choose the server IP of the interface that received the packet (match the sender's subnet); skip virtual adapters (Hyper-V, WSL, VPN) when choosing.

## 7. Server: Windows specifics

- Build: a console build with an embedded version string (`build.ps1` → `dist\minimedia.exe`, plus the TV app APK).
- **ffmpeg discovery**: `ffmpeg.exe`/`ffprobe.exe` next to the exe → config paths → `PATH`. README: download a "full" build (gyan.dev, includes zscale) or `winget install Gyan.FFmpeg`.
- **No Windows service** (the user's decision, 2026-11-16, at the start of Phase 5): MiniMedia runs as a normal program; the README explains starting it at logon with a Startup-folder shortcut. `log_file` (when set) rotates at 10 MB, keeping 3 old files.
- **Firewall**: README documents allowing it on the first-run prompt (**Private networks**), and the fallback command:
  `New-NetFirewallRule -DisplayName "MiniMedia" -Direction Inbound -Program "<path>\minimedia.exe" -Action Allow -Profile Private`.
  On startup, log a warning if the active network profile is Public (discovery will be blocked).
- **Prevent sleep while streaming**: when any stream is active, call `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)` from a dedicated goroutine locked to an OS thread (`runtime.LockOSThread`), and clear it 2 minutes after the last stream request. macOS and Linux: see 7.1.
- **Child processes**: put every ffmpeg/ffprobe process in a Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` so they die if the server exits or crashes. Use `CREATE_NO_WINDOW` so no console windows pop up. On Unix use process groups and kill the group.
- **Paths**: long paths (`\\?\` prefix when > 240 chars), case-insensitive comparisons for de-duplication, Unicode file names (Romanian diacritics) tested.
- Graceful shutdown on Ctrl+C and SIGTERM: stop jobs, flush DB.

### 7.1 macOS and Linux (added 2026-11-17)

- **Build**: the server is pure Go (no cgo), so `build.ps1` cross-builds `minimedia-macos-arm64/-amd64` and `minimedia-linux-amd64/-arm64` next to the Windows exe; `build.sh` builds for the current machine on macOS/Linux.
- **ffmpeg**: 5.1 or newer is required everywhere (`-fps_mode`, `noise=drop`); the version is checked at startup with an OS-specific install hint (Homebrew; Debian 12+/Ubuntu 24.04+ packages or a static build). Verified on Ubuntu 24.04 with ffmpeg 6.1.
- **Sleep**: a helper process holds off sleep while streaming: `caffeinate -i` on macOS, `systemd-inhibit --what=sleep:idle --mode=block` on Linux. Its stdin is a pipe from the server, so it exits if the server dies. Linux only allows this in a logged-in session; when refused, the server logs one warning and stops trying.
- **Folder watching**: Linux uses fsnotify (inotify, a watch per folder). macOS polls every 30 s (sizes and modification times of the tree), because kqueue needs an open file per watched file and network mounts send no events.
- **Child processes**: process groups as before; on Linux `Pdeathsig=SIGKILL` also kills them if the server is killed. macOS has no equivalent, so a running ffmpeg finishes its job.
- **Start automatically**: README examples for a LaunchAgent (macOS) and a systemd user unit (Linux). Neither is a system service.
- **Firewall**: README covers the macOS application firewall prompt and ufw/firewalld rules; no startup check.

## 8. Google TV app

### 8.1 Stack
- Kotlin, `minSdk 31`, `targetSdk` = latest stable, Android TV only (`android.software.leanback` required, `android.hardware.touchscreen` not required, `LEANBACK_LAUNCHER` intent filter, 320×180 banner).
- **Compose for TV** (`androidx.tv:tv-material`) + Navigation Compose, ViewModels, Kotlin coroutines/Flow.
- **Media3**: `media3-exoplayer`, `media3-exoplayer-hls`, `media3-ui` (use `PlayerView` with `useController = false` inside `AndroidView`, for video surface and `SubtitleView` rendering; all controls are custom Compose).
- OkHttp + Retrofit (or Ktor client) with kotlinx.serialization; Coil 3 for images; DataStore for settings.
- Build and install from Android Studio on Windows; deploy to the Chromecast via ADB over Wi-Fi (README covers enabling Developer options and `adb connect <tv-ip>:5555`).

### 8.2 First run
- Discover servers via UDP broadcast (acquire a `WifiManager.MulticastLock` while discovering; retry 3× over 3 s). One server → connect automatically. Several → pick from a list. None → manual entry screen (`192.168.1.20:8096`) with a numeric-friendly on-screen layout.
- Remember the server by `serverId`; if its IP changes, rediscover automatically on connection failure.

### 8.3 Screens
- **Home**: hero banner (backdrop, TMDB logo or title, year · runtime · genres, overview, Play/Resume and More Info buttons; rotates every 10 s while focused out). Rows: Continue Watching (with progress bars), Next Up, Recently Added Movies, Recently Added Episodes, Movies, Shows. The focused card updates the hero backdrop (Netflix-style). Top navigation: Home, Movies, Shows, Search, Settings.
- **Movies / Shows**: poster grids with sort (title, recently added, year) and genre filter.
- **Details (movie)**: backdrop, logo/title, `2021 · 1h 52m · Ends at 22:49`, genres, overview, buttons: Play/Resume, Play from beginning, Audio & Subtitles, Mark watched.
- **Details (show)**: season tabs; episode list with still, `S1 · E2 Title`, runtime, `Ends at`, progress bar, watched check, overview. Default focus on the next-up episode.
- **Search**: TV on-screen keyboard + voice search via the remote's mic (`RecognizerIntent` / Assistant search integration optional); results as rows.
- **Settings**: server (rediscover, manual), subtitle appearance (size S/M/L/XL, background none/shadow/box, position), default languages, autoplay next episode, "Are you still watching?" on/off, about.

### 8.4 Player (the most important part)
Layout (controls visible): top-left title and `S1 · E2 · Episode title`; bottom: seek bar with elapsed (left) and remaining `-1:12:03` (right), and `Ends at 22:49` under the bar; a row of buttons below: Play/Pause, Audio & Subtitles, Speed, Episodes (shows), Next Episode (shows).

**Remote behaviour**
- Controls hidden:
  - OK / Play-Pause → toggle pause and show controls.
  - Left / Right → jump −10 s / +10 s immediately, with a "−10" / "+10" badge; repeated presses within 1 s accumulate (+20, +30…).
  - Up / Down → show controls.
  - Back → exit the player (save progress).
  - Media FF/RW keys (if present) → ±30 s.
- Controls visible, focus starts on the seek bar:
  - Left / Right → **scrub mode**: playback keeps running, a scrub head moves along the bar, and the **trickplay thumbnail** with the target time is shown above it. Step 10 s per press; while held, accelerate (10 s → 30 s after 1 s → 60 s after 3 s; on files > 2 h, also allow 2 min steps). The `Ends at` label updates live for the target position.
  - OK confirms the seek; Back cancels scrub mode; after 2 s without input the seek is committed automatically.
  - Down → button row; Up from the buttons → seek bar.
  - Controls auto-hide after 5 s without input (never while paused with a panel open).
- Paused: show controls, a dimmed scrim, and keep `Ends at` moving forward with the clock.

**Trickplay in the app**
- On player start, fetch `index.json` and prefetch all sheets in the background (Coil/OkHttp disk cache). Decode sheets with `inSampleSize = 1`, keep an LRU of ~6 decoded sheets. Crop the tile with `Bitmap` source rect drawing (no per-tile copies).
- No trickplay yet → show the time label only.

**Skip Intro / Recap**: when position is inside an `intro`/`recap` marker, show a "Skip Intro" button bottom-right with focus on it (even with controls hidden); OK seeks to `endMs`. Hide after 10 s or at the marker end.

**Next episode**: at the credits marker (or the fallback point from 3.6), show a card bottom-right: next episode still, title, "Next episode in 10…". OK = play now; Back = dismiss and keep watching the credits; countdown end = play next. After 3 consecutive autoplayed episodes with no remote input, show "Are you still watching?" instead of autoplaying.

**Resume**: if `resumeMs` > 0, show a dialog before playback: "Resume from 42:10" (default) / "Start from beginning".

**Audio & Subtitles panel**: two columns (audio tracks, subtitle tracks + Off). Labels like `Romanian`, `English (Forced)`, `English 5.1 (E-AC3)`. Changing audio may require a new playback session (HLS for a different audio index) → re-request playback and resume at the current position seamlessly. Store the choice via `PUT /api/shows/{id}/prefs` for episodes.

**Subtitles**: external sidecars passed as `MediaItem.SubtitleConfiguration` (MIME from the server, `language`, `label`, `C.SELECTION_FLAG_FORCED` for forced). Forced tracks auto-enable when the audio language differs from the subtitle language and subtitles are otherwise off. Style via `SubtitleView.setStyle(CaptionStyleCompat)` + text size from settings.

**Speed**: 0.5, 0.75, 1, 1.25, 1.5, 2 (audio pitch preserved).

**Ends at**: `end = now + (durationMs − positionMs) / speed`, formatted with `DateFormat.is24HourFormat(context)` (24 h → `22:49`). Recompute every 30 s, on seek, on speed change, and live while scrubbing (using the scrub target). Same formula (speed 1, current progress) on details pages and episode lists.

**Robustness**
- Buffering spinner after 500 ms of buffering only (avoid flicker).
- Player error on direct play (decoder/format failure) → automatically retry once with `forceConvert: true` from the same position, then show a readable error ("This file's video format (AV1) isn't supported by this device").
- `unsupportedReason` from the server → show it on the details page and disable Play.
- Progress reporting as in 4.5; on exit, send the final position before leaving the screen.
- Keep the screen on during playback; release the player on stop; handle the Home button (pause and save progress in `onStop`).
- Frame rate / HDR: set `setVideoChangeFrameRateStrategy(C.VIDEO_CHANGE_FRAME_RATE_STRATEGY_ONLY_IF_SEAMLESS)` by default and rely on the Google TV system "Match content frame rate" setting; mention it in the README.

### 8.5 Device capability detection (for 4.1)
- Video: `MediaCodecList(REGULAR_CODECS)` → decoders for `video/avc`, `video/hevc`, `video/x-vnd.on2.vp9`, `video/av01`.
- HDR: `display.hdrCapabilities` / `Display.Mode.supportedHdrTypes`.
- Audio decoders: `audio/mp4a-latm`, `audio/ac3`, `audio/eac3`, `audio/opus`, `audio/flac`, `audio/vorbis`, `audio/mpeg`, `audio/vnd.dts`, `audio/true-hd`.
- Passthrough: Media3 `AudioCapabilities.getCapabilities(context, audioAttributes, null)` → `supportsEncoding(C.ENCODING_AC3 / E_AC3 / DTS / DOLBY_TRUEHD)`; `maxChannels` from the same.
- Recompute when the audio route changes (HDMI receiver turned on/off) and before each playback request.
